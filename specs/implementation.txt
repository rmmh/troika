TROIKA NATIVE ECOSYSTEM IMPLEMENTATION EVIDENCE
===============================================================================

The network, storage, transport and web files describe the target. A passing
hardware unit test does not prove native firmware, a usable application or
the complete 19683-tryte RAM requirement. Keep those gates distinct.

Implemented and exercised:
  - Specified mode-T character-ROM display: src/core/textDisplay.ts renders
    27x27 ASCII cells from page zero and all signed palette selectors without
    reading code pages or modifying guest RAM. Native instructions select it;
    the web display and REPL screenshot path share fixed glyphs. Pixel and
    browser UI tests cover rendering and returning from memory inspection.
    Native text.asm converts every Troika text code to ASCII and draws counted
    strings with row wrapping, LF handling, signed palettes and screen clipping.
    Native browser page layout and input remain open.
  - Exact client allocation with real MMIO/screen/palette placement:
    src/firmware/layout.ts; test/firmwareLayout.test.ts.
  - Atomic selected-unit block hardware, busy/selection semantics, independent
    submission/completion, media generations/change masks, reset/power-loss
    behavior and event IRQs: src/core/blockDevice.ts; test/blockDevice.test.ts.
  - Native block read/write/flush driver, including RAM-to-disk-to-RAM transfer
    on a nondefault drive through Machine instructions: firmware/include/block.asm
    and test/nativeBlock.test.ts. No filesystem semantics live in hardware.
  - npm run firmware:report assembles native modules and reports emitted cells.
    src/firmware/link.ts relocates modules across the three ordinary resident
    extents, iterating jump relaxation with monotone reservations. A bounded
    memoized packing search recovers layouts that greedy placement misses,
    including an exact full-capacity fixture ending at address 9841. It accounts
    for un-emitted buffers and requires explicit opt-in to consume margin.
    Native routed scenarios execute these relocated images, not a flat layout
    that could grow into palette/MMIO. This still does not prove full client fit.
  - First native FAT read path: firmware/include/fat.asm and test/nativeFat.test.ts.
    Directory enumeration, nested paths through eight levels, FAT cache page boundaries,
    exact chain lengths, file padding, handle ownership and media replacement.
    The deepest tested read path uses at most six native stack cells.
    Host src/firmware/diskImage.ts only formats initial scenario fixtures.
  - Native offline FAT/tree checker and explicit orphan reclaim:
    firmware/include/fatCheck.asm. Rejects duplicate siblings, cross-links,
    ancestry cycles, reserved FAT corruption and invalid file tails. Repair
    does not follow unreachable directory copies to delete their live children.
  - Checked-mount same-size native file-block overwrite (fatWrite.asm), including
    read-only rejection and storage snapshots before/after commit followed by
    native reboot/read verification. No unchecked-volume write is permitted.
  - Native create/replace/delete/mkdir/rmdir and copy-on-write directory growth:
    fatMutate.asm, fatGrow.asm, fatAdmin.asm and nativeMutate tests. Reboots after every atomic
    replacement/growth write expose complete old or new contents; native reclaim
    preserves live child chains. Tests cover full media/root/directories, FAT
    page boundaries, read-only media and mounted/other-unit replacement. The
    implementation reuses the existing 567-cell filesystem working set.
  - Cooperative native disk polling: an optional two-cell callback/guard in
    protocol RAM preserves live registers and rejects all public filesystem
    reentry, including close/abort. Native stream payload receipt progresses
    during a ten-block atomic file replacement; both payload and file survive
    unchanged, with stack use bounded by 54 cells in this integration test.
    Durable serial refills suspend callbacks to avoid protocol recursion.
  - Native durable serial reservation (serial.asm): full-width carries,
    exhausted sentinel, pinned volume, monotonic bound, range consumption while
    a file is open, and crash/reboot checks. Protocol state costs 17 trytes.
  - Native FAT/serial tests instrument CPU bus writes to reject code or RAM
    outside the declared mutable regions. Serial tests bound observed native
    stack use to 16 cells; this is not yet a network-active browser measurement.
  - NIC Q/R and LAN fabric: fixed five-frame hardware storage, immutable sends,
    source stamping, RX overflow, local broadcasts, identity ordering and ticks.
  - Shared World coordinator: actual instruction costs, deferred boundary IRQs,
    single world clock, sleeping CPU jumps and external block/NIC timing.
    Tests cover CPU-count independence, in-flight division, timer/delivery ties,
    local/external interrupt priority and interval partition independence.
  - Native Q/R frame send/receive/clock driver and structural protocol validator:
    firmware/include/netDevice.asm and frame.asm; test/nativeNetwork.test.ts.
    A two-machine datagram exchange builds/replies/validates using native code
    and shared-world physical delivery. This is not yet routed transport.
  - Native next-hop selection, neighbour retries/cache expiry, and two-interface
    router firmware: network.asm/router.asm. Tests route datagrams/replies over
    one and two routers, preserve end-to-end tuples, and terminate route loops.
    Native ICMP echo, no-route, neighbour-failure and hop-exhaustion replies
    include serial/header matching, rate limiting and error-loop suppression.
    Control resolution preserves owned RX and retained unacknowledged TX data.

  - Native DNS canonicalization, record-table validation/search and routed
    client/server queries: dns.asm, dnsClient.asm, dnsServer.asm and nativeDns
    tests. One-entry cache, strict reply matching, bounded retries, query
    cancellation and expiry run entirely in guest RAM/instructions.

  - Native DHCP lease table and client state machine: dhcpServer.asm and
    dhcpClient.asm, tested on two guest CPUs. Includes durable transactions,
    bounded retries, matching ACK/NAK, conservative lease timing, renewal,
    expiry/link-loss cleanup and preservation of retained application TX.
    Applications must wire the lease-loss callback into their DNS/stream state.

  - Native bootstrap integration on four guest CPUs: an initially unconfigured
    client acquires its address/gateway/DNS from DHCP on LAN A, then resolves a
    DNS name on LAN B through the router. The lease-loss callback invalidates
    DNS state. This fixture passes with audited CPU writes and bounded native
    stack use, but is not yet an interactive world/browser application.

  - Native reliable-stream handshake core: stream.asm / nativeStream tests.
    Durable A/B reservation, duplicate coalescing, strict endpoint/serial checks,
    bounded OPEN/OPEN-ACK retries, control priority and busy/refused RESETs.
    Tests lose each handshake packet, hold a native file handle during B
    allocation, and preserve retained data during duplicate-handshake replies.
    streamData.asm adds maximum-size bidirectional payloads, incremental reads,
    strict backpressure, duplicate suppression, FIN/tombstone, local/remote abort,
    ingress deadline checks and full-quote ICMP correlation. Tests cover lost
    DATA/ACK/FIN, partial-read timeout cleanup, sequence 9840/9841, and reboot
    separation using the actual durable disk images. Complete application
    integration and full browser memory fit remain separate gates.

  - Native bounded Forth VM and page-word backend: forthVm.asm/forthPage.asm.
    Bytecode fixture tests cover stack/return limits, signed arithmetic, exact
    729-instruction budget, recursion without native stack growth, slice-scoped
    reads, variable-only writes, overlapping text updates and action cleanup.
    Native streamed compilation is implemented by forthLex.asm/forthCompile.asm:
    token/comment chunking, checked literals, declarations, stable bindings,
    conditionals/loops, recursion and deferred adapters. Exact arena/variable/
    control limits are tested. A native stream fixture compiles received source
    and invokes LOAD at complete EOF; truncated source executes no handler.
    url.asm implements the native navigation hook: canonical world URLs,
    bounded path/port grammar, numeric addresses, explicit origin commit and
    same-origin form paths. Compiled GO is tested against this real parser.
    HTTP/page acceptance is exercised below; interactive browser integration
    is still open.

  - Native HTTP/T1 incremental request/response parser and response encoder:
    http.asm/httpEmit.asm. Exact header/body limits, duplicate recognized
    headers, native Host matching, unknown-method policy, callback reentry,
    truncation and extra data are tested. A native client/router/server fixture
    serves empty and multi-block FAT files with lengths derived on the guest,
    checks received bytes and completes both stream halves. The httpRequest
    server module is excluded from browser images; httpClient retains response
    framing and explicitly rejects request mode. Role-specific measurement
    avoids charging server-only parsing to the browser without dropping it
    from actual server images.

  - Native browser request-header encoder: httpSend.asm. GET and same-origin
    /app/ POST headers use at most 159 cells of existing scratch. Canonical
    authority, nondefault ports, exact decimal lengths and origin rejection
    are exercised against the native server parser. Routed FAT-file tests now
    generate the client's GET header on its guest CPU rather than injecting
    preformatted HTTP. Submission control remains open.

  - Native incremental Troika-page/plain-text loader: page.asm. Counted literal
    strings, 27 records, form ordering, three unique input names, fixed input
    reservations, discarded/streamed C source and exact text/wire bounds are
    tested. HTTP/page/Forth tests reject incomplete or extra body data before
    LOAD; plain text remains inert. Link checks preserve the pending origin
    using the existing native stack, bounded by 110 cells in these tests.

  - Native page form encoder: pageForm.asm serializes current input values in
    page order into the existing scratch arena, including empty values and the
    exact 208-cell maximum. It rejects invalid edited values and active handler
    reentry. A native HTTP parser receives the complete emitted POST body after
    header/body scratch reuse. Server form validation and dispatch remain open.

  - Native disk-backed image replacement: image.asm and build-time formatter
    nativeImage.ts. Tests load/execute complete files, call resident routines,
    replace code, clear stale tails and reject corrupt/truncated/oversized
    images. Media loss and callback reentry leave partial images uncallable.
    A 1906-cell slot is reserved within ordinary guest code RAM; six existing
    protocol cells hold loader state. Native phase tests now replace compiler
    code with interaction code while retaining the sealed dictionary/page.
    LOAD, SUBMIT, form encoding, request headers and text drawing execute after
    replacement; a second navigation reloads the compiler and repeats the cycle.
    These tests include the full resident browser library set, but not its
    network controller or network-active phase transitions.

  - Native page viewport: pageView.asm lays out accepted page records or inert
    plain text directly into the 27x27 text screen. It wraps text, hides F/C
    records, brackets links/buttons, draws input names and values, highlights
    the focused record and clips by caller-owned logical scroll row. Interaction
    phase operation 5 accepts top row in C and focus in D; it returns total rows
    in B. Eight cells at 5439..5442 and 5449..5452 hold metadata, including the
    focused record start row and caret position; no layout buffer is allocated.
    Tests cover maximum text, exact-width wrapping, scrolling, empty pages,
    rejected state and rendering after native disk phase replacement.

  - Native focus and input editing: pageInput.asm traverses L/I/S records in
    both directions with wraparound, and inserts/backspaces/deletes within the
    existing 54-cell value reservation. No persistent state is added. Tests
    check empty/full inputs, cursor edges, unchanged surrounding page data,
    rejected arguments/state, serialization/rendering after editing and calls
    through a disk-loaded interaction phase. pageUi owns interaction state.

  - Native page interaction controller: pageUi.asm owns focus, edit cursor and
    top row in six cells at 5443..5448. Events traverse focus, edit values, move
    the cursor, scroll and activate links or SUBMIT. The viewport follows a
    newly focused record and clamps manual scrolling. Link activation uses the
    accepted origin and native URL parser, then publishes a deferred GO action.
    Pending actions reject further UI events until the network controller resolves
    them; no request or origin commit occurs in this module. Tests exercise
    phase-loaded UI calls, rendering after editing, distant focus, literal plain
    text, handler errors and action freezing. Network control and complete application lifecycle remain open.

  - Physical text keyboard: the focused mode-T canvas forwards printable and
    control keys through the existing text device; Escape releases focus.
    pageKeys.asm polls one key and invokes the native UI controller. Pending
    actions and active parser/handler state retain queued keys without consuming
    them. Unit/guest tests cover translation, edits, invalid controls and queue
    retention; a disk-loaded phase test exercises polling, and browser tests
    verify actual key forwarding. No additional guest state cells are allocated.
    The application still needs a cooperative network/UI polling loop.

  - Native edit caret: the viewport tracks the insertion position while walking
    input text and marks its screen cell with palette 2. UI scrolling follows
    the caret through wrapped and multiline values. A trailing display blank
    prevents end carets from covering the next record. Tests check glyph/value
    preservation, exact-width wrapping, 54 literal newlines, offscreen clipping,
    focus changes and a caret after keyboard editing in the loaded phase.

  - Deferred request preparation: pageRequest.asm resolves SEND to its form
    target and same-origin POST, or GO to a GET without committing its origin.
    Header/body stages reuse shared scratch and reject duplicate/out-of-order
    preparation. Pending actions freeze both UI and lower-level native editing
    until completion/cancellation. Two metadata cells at 5453..5454 hold stage
    and body length. Tests check header/body agreement, cancellation, unchanged
    committed origin, missing origin and disk-loaded phase dispatch. Retry policy and response loading remain application work.

  - Cooperative request sender: pageTransmit.asm sends the prepared header and
    body through native stream_send, preserving scratch ownership and frozen
    values across backpressure. Two cells at 5455..5456 track send phase/header
    length. It queues FIN after final DATA acknowledgment and releases the action.
    Guest client/server tests validate a GET and maximum 208-cell form POST,
    complete stream closure and exact body delivery after dropping DATA and ACK.
    The interaction image includes this sender; those network tests use separate
    linked fixtures, so network-active disk replacement is still unproven.

  - Native pending-URL connection setup: browserConnect.asm resolves hostnames
    with the native DNS client or uses numeric addresses directly, then starts
    and observes the reliable-stream handshake. It copies the endpoint into
    seven protocol cells at 2493..2499, leaving origin identity unchanged.
    Action-target resolution now precedes DNS; headers are generated afterwards
    because DNS normalization and header generation share scratch. Tests cover
    GET/maximum POST after DNS, numeric GET, packet loss, missing names, refused
    endpoints and busy reentry. The resident connector is included in the full
    phase fixture and RAM inventory. Cooperative ingress dispatch, response
    loading and complete application lifecycle still need integration.

  - Resident response loading: browserResponse.asm consumes owned stream DATA
    through native HTTP framing and dispatches each body cell into the disk-loaded
    compiler image. EOF is required before page sealing and origin commit; LOAD
    remains deferred until the interaction image is installed. Empty untyped
    responses become empty plain pages; non-200 executable pages and non-page
    content types are rejected. Four protocol cells at 2500..2503 hold response
    state. A full-resident-library fixture tests actual FAT image loading, fixed
    text capacity, absolute-link validation, framing failures and unchanged old
    origins on failure, with observed stack use bounded by 120 cells. Its stream
    DATA/EOF inputs are injected fixtures, not yet a live end-to-end navigation.

  - Download mutation phase: downloadPhase.asm loads atomic replacement and
    directory growth only while saving a file. The resident checked filesystem,
    offline checker and durable serial overwrite remain unchanged. Native FAT
    tests load the phase, replace a binary file, grow a full directory and abort
    an unpublished replacement, then reload interaction code with the retained
    page unchanged. No extra state arena is allocated. Moving these routines
    out of resident code frees 843 cells after relinking. downloadBody.asm now
    assembles raw HTTP body cells using the existing filesystem block buffer,
    requires status 200 and publishes only after valid EOF. Truncation aborts
    the unpublished replacement; retained page and origin remain unchanged.
    Five protocol cells at 2506..2510 select download mode and track assembly.
    Native download navigation is now integrated with the resident browser loop.

  - Resident navigation loop: browser.asm mounts/checks disk, installs native
    phases and sequences target resolution, connection, transmission, compiler
    loading, response acceptance, interaction loading, LOAD and UI polling.
    Its callback-safe network pump preserves owned stream bodies during disk
    reads and services DHCP/DNS/streams. Two cells at 2504..2505 hold state and
    sticky status. A live two-CPU fixture loads all phase files through FAT,
    navigates to a Forth page, runs LOAD, edits via the text device, POSTs and
    displays a plain response. It observes DATA retention during image loading,
    rejects a corrupt compiler image and bounds stack use by 120 cells. That
    complete prototype including native startup fits the declared RAM layout.
    The fixture also covers native DHCP startup and renewal, remote DNS and a
    router across two LANs. browser_download_open accepts URL and a stable local
    destination, performs GET through /download and restores /interact without
    rerunning LOAD or changing the displayed page, focus, caret or origin.
    Three protocol cells at 2511..2513 hold intent and destination. Live native
    tests verify binary publication, unchanged files on HTTP error and normal
    form submission after a successful download. Address-entry/download-choice
    UI, local-error UI and cancellation remain open.

  - DHCP browser startup: browserDhcpBoot.asm provides a native example entry
    using NIC Q, system volume [0,0,1], DHCP and http://bbs.world/index. It waits
    for a bound lease before navigation. A five-CPU fixture executes startup,
    native DHCP renewal, remote DNS, routing, page LOAD, keyboard editing and
    POST across live disk-phase replacement. No host service implements those
    decisions; host code only assembles images and supplies hardware topology.

Measured role-library checkpoint (npm run firmware:report):
  - Resident-only browser: 12374 emitted cells, 12385 reserved after relocation, out of
    12501 code cells including explicit margin. Only 116 cells remain for
    application code. This includes native text drawing but not browser layout.
    Text mode uses only 54 live palette cells; reclaiming 189 formerly padded
    cells restores this library link. Tests execute native code on both sides
    of the palette and verify that all 54 live cells remain unchanged.
    Directory creation/removal and file deletion remain optional fatAdmin;
    the browser retains atomic download replacement and directory growth.
  - HTTP server: 8227 code cells; router: 4235; DNS server: 4030; DHCP server:
    4168. These are separate machine images, not simultaneous browser modules.
  - Separate image-loader fixture: 2018 emitted / 3924 reserved cells including
    its 1906-cell slot. The resident-only browser inventory above excludes this
    loader.
  - Phased browser libraries: 10085 resident emitted / 11991 reserved, including
    one 1906-cell slot at 7007. Compiler phase: 1869 cells; interaction phase:
    1834 cells; download phase: 1008 cells. Thus 510 code cells remain outside
    the slot, and 72 are unused within the interaction phase. These amounts are not interchangeable across
    phases. All three dispatchers, the loader and page UI are charged;
    address-entry/download-choice UI, cancellation and local error UI still need implementation and measurement.
  - DHCP startup prototype: 10165 resident emitted / 12071 reserved including
    the same slot, leaving 430 code cells. This includes the entry jump, native
    DHCP wait loop and home URL. The tested GET/POST prototype fits; the complete
    browser and ecosystem requirements are still not implemented.
  - Role-library counts include inert hooks where specified; the DHCP browser
    prototype uses actual navigation, lease-loss and HTTP-body callbacks.
    The native navigation loop is included; startup configuration is excluded.
    This measured library fit does not establish complete browser fit. Margin
    placement alone is not the remaining total code capacity.
  - Re-run the report after code changes; these counts are a checkpoint, not
    reserved space for the remaining features. Maximum integrated stack use
    must also be measured with real application callbacks and network activity.

Still required before claiming the requested ecosystem works:
  - Complete file/stream application integration, including download commit
    and cancellation semantics in the browser and shell.
  - Coherent whole-world replay/snapshots.
  - Native ping/traceroute utilities,
    and the application servers. Router ICMP generation alone is not a utility.
  - Full HTTP application integration, TELNET and interactive Forth/browser integration,
    origin enforcement, native display/input, file download and DOS-like shell.
  - Persistent BBS/forum/filesharing services, games and defensive security
    demonstrations. All service decisions execute on native guest CPUs.
  - First topology: two LANs, router, DHCP, remote DNS/HTTP, door/bell and
    noticeboard; player and NPC browsers. Extend with the larger ecosystem.
  - Complete assembled client/server/router images, maximum-size input runs,
    stack high-water measurements during network activity and no hidden host
    parser/protocol/filesystem/script state. Total fit remains UNPROVEN.

This evidence list records open work; it does not reduce the requested scope.
Host fixtures may format initial disks and assert results. They cannot stand
in for native FAT routines, service handlers, routing, or the Forth runtime.
