TROIKA EXPANDED WEB
===============================================================================
Goal: at least 100 distinct, browsable sites connected by thematic webrings,
with small graphical embeds and enough authored content to feel inhabited.
Most sites may be static. Guest-driven change is optional enrichment, not a
substitute for writing substantial, varied content. Existing forums, games,
chat, file sharing and appliance exercises remain part of the world.

The existing native constraints remain: guests resolve names, handle HTTP,
read files, parse pages and render into their own 19683-tryte RAM. Host code may
build initial images and emulate hardware; it must not answer website requests,
perform virtual-host dispatch or interpret graphic records for the browser.

Planned implementation boundaries
-------------------------------------------------------------------------------
- Curate at least 100 individually named sites, organized into themed rings.
  Favor distinct perspectives and concrete material: personal field notes,
  repair instructions, recipes, fiction, galleries, local notices, collections,
  reviews, puzzles and reference material. Avoid one generic paragraph with
  substituted names. Sites need useful internal pages and related-site links.
- Native virtual hosting should share a small number of server CPUs among
  multiple Host names. Native dispatch must validate the requested host before
  selecting its on-disk root, preserve origin separation, and retain the
  existing bounded concurrent-client behavior. Initial content lives in real
  block images with measured capacity. Measure startup work before choosing
  cluster sizes; adding 100 full cold filesystem scans is not an acceptable
  default boot path.
- Ring navigation should provide previous/next/hub links and cross-ring finds.
  A native directory page should make discovery possible without typing URLs.
  Every advertised site and link must resolve and load through native DNS/HTTP.
- Small graphics should be explicitly bounded page records with alt text,
  rendered by native firmware into text-mode block glyphs. The host renderer
  may implement fixed device glyphs, but must not parse page image descriptions.
  Charge retained image cells and descriptors against existing page arenas,
  and keep graphics readable while scrolling and using the keyboard.
- A few established interactive services and autonomous native visitors can
  supply activity. Most sites should be interesting without requiring edits,
  submissions, or continuous background computation.

DNS scaling foundation (selected by the expanded world)
-------------------------------------------------------------------------------
src/world/dnsProfile.ts provides an optional native compact-table profile:
108 records x 24 cells at 2552..5143, below the echo slot at 5333 and stack at
5468. A record has length, 18 name cells, address[3], TTL and one reserved zero.
The ordinary 27-record/54-cell-name server remains unchanged. Full protocol
queries still accept up to 54 canonical name cells; absent long names receive
not-found normally. This profile is an option for short site names, not a
protocol limit or a requirement that all future names be short.

Guest code validates capacity, canonical spelling, padding, address, TTL and
unique names before listening. Lookup and replies execute dnsServer firmware;
the TypeScript helper only specializes the initial assembly and formats records.
Tests exercise a full 108-record table, bad configuration, and real client/server
queries for first, middle and last records plus a long absent name. Disk indices
remain an available native design if the catalog or hostname lengths call for
more capacity; no host DNS map may substitute for that implementation.
The current lookup is a linear RAM-table search, not a disk scan. Startup checks
duplicates against earlier records, so validation is quadratic in the record
count. The populated world uses 106 names; additional programs on existing sites
do not consume DNS records. Exceeding the table capacity can use a native
disk-backed index rather than requiring all records to remain resident.

Native virtual-host serving (installed in the expanded world)
-------------------------------------------------------------------------------
src/world/virtualHostImage.ts links a read-only HTTP profile with up to 27
configured canonical names per server, including full 54-cell protocol names.
httpVirtual.asm compares the parsed/normalized Host and port 80 with a native
firmware table, then selects a three-character directory below /public. The
selected directory pointer lives in h_host_match inside the existing parked
HTTP context. No pending URL state needs to survive another client's parsing.
GET / maps to that host's index; missing/unknown origins return 404. Narrow
native path validation rejects traversal. POST/PUT return 405 after complete
framing, without parsing form descriptors into parked transport memory.

Two 383-cell HTTP banks occupy 2552..3317, ingress 3318..3560, and two 633-cell
transport banks 3561..4826. These replace unused page arenas; resident code,
echo, native stack, filesystem and active stream buffers keep their boundaries.
The existing native three-client scheduler and NIC-interrupt waits remain.
nativeVirtualHosts tests use real CPUs, NICs and block media to hold three
responses simultaneously and compare each distinct returned body. They also
cover Host normalization, unknown/numeric/wrong-port origins, root confinement,
malformed paths, full-length names and concurrent rejected mutations.

The original 20-site fixture (one 500-cell body per site, 243 physical blocks)
checked/mounted in approximately 5.1 million guest world cycles before listening.
The headless profile now dedicates screen RAM -9841..-9113 to a 729-cell native
reference window, replacing the generic checker's 18-cell window. It retains
all FAT/tree/duplicate/tail validation, orphan reporting and explicit repair;
larger media still use multiple bounded passes. Those cells cannot also serve
a display or another scratch buffer. The browser/general checker is unchanged.
An isolated populated-disk check falls from 4,978,974 to 2,698,496 guest cycles.
The virtual-host boot regression has a 3.1-million-cycle limit. Cross-link tests
span reference-window and FAT-page boundaries and verify no premature repair.
These are fixture measurements, not acceptance claims for the forthcoming
larger catalog: cluster sizing still requires the actual content images.

Authored catalog (installed in the expanded world)
-------------------------------------------------------------------------------
src/world/catalog contains 100 separately written sites in ten thematic rings:
field observations, workshops, kitchens, arts, local life in fictional Mere,
games, science, short fiction, object collections and personal pages. Every
site has its own introduction and a complete feature page. These include actual
recipes, repair/experiment notes, game rules, reviews, diary entries and stories;
no visitor posts are required to make the sites readable.

pages.ts formats 211 initial native PAGE documents: two pages per site, ten
ring directories and the atlas home. Each site links to previous/next neighbors,
its ring directory, the atlas and a recommendation in another ring. Five
243-block images hold these files below separate native virtual-host roots;
server 100 holds the atlas too. With illustrations, free blocks are 42, 88,
88, 88, 88. All 101 names
fit the optional compact DNS profile alongside the existing world names.
webCatalog.test checks all link destinations, reachability from the atlas and
closed ten-site rings. It also feeds every document through the native parser,
checking actual text/record consumption and memory boundaries. These tests are
complemented by the production navigation checks below; they do not by
themselves prove routed DNS/HTTP delivery or visual presentation.

Production integration and current evidence
-------------------------------------------------------------------------------
The program desktop enables the expanded web by default. createStarterWorld
also accepts web:true for a legacy browser fixture, or web:false to isolate
other tests. Both world.html and the root debugger's World view use the program
desktop. The BBS home now links to the atlas; the surrounding controls document
the console route for retained disks whose old home page lacks that link.
Five native machines web100..web104 serve the disk images on LAN b. The compact
DNS table holds all 106 names (five original names and the 101 catalog names).
The machine inspector includes each new CPU, memory and linked firmware labels.
Web/CLI power-on waits for their native initialization; failure codes are
reported. Snapshots include their CPU/device/media state automatically.

webCatalogWorld.test follows the atlas, field ring, moss article, next/previous
neighbors, a cross-ring recommendation on a different server, and the last
personal site entirely through physical keyboard events. It checks scrolling,
site-local Home, committed origins, successful HTTP status and server code
write boundaries. All five populated servers are initialized and sleeping at
about 3.95 million world cycles. CLI --smoke --programs reaches the home page
with 19 native CPUs in about 10.87 million cycles. starterReplay verifies
snapshot/replay during boot IO and later input with the expanded configuration.
Actual server code budgets are 9433..9472 of 12501 available cells.

Article pages place a Site home link near the heading so initial keyboard focus
does not scroll past the opening text to expose a footer. Every article also
retains footer navigation. All 211 revised pages pass native parser validation.
The seven existing world browser tests pass with the expansion enabled. An
additional atlas browser check opens the directory through the native console,
selects web100 in the inspector, and reads its ready cell (2198 = 1). The atlas
and memory-view screenshot was inspected. Desktop switching, disk checkpoints,
camera/alarm behavior and live snapshot replay also pass their regressions.

Native graphical page records and catalog illustrations (implemented)
-------------------------------------------------------------------------------
G records retain 54 packed quadrant symbols plus a 1..54-cell caption in the
existing text arena. Native parsing checks lengths and every raster symbol.
Native viewport code draws 18x12 pixels through the mode-T quadrant ROM, clips
them at viewport edges and displays the caption below. The fixed ROM has 16
new glyphs, not a host image/page interpreter. Images consume one ordinary
record descriptor; keyboard focus skips them. Tests cover fragmented loading,
all quadrant masks, malformed payloads, scrolling/clipping, captions and exact
text-arena limits. All 125 page/display tests pass and both browser profiles fit
their original 1906-cell phase slots: compiler 1900, program interaction 1871,
legacy interaction 1903. A disk-phase test retains a G page across replacement
and renders it through the resident helper without changing its payload.
Eleven authored bitmap assets depict the atlas globe and the ten rings. All
111 home/directory pages contain an image with a readable caption. The 211-page
native parser audit includes these records. Browser verification reads the
atlas caption and checks actual green bitmap pixels; its screenshot was
inspected. Shapes come from the disk payload, while the host supplies only
the fixed 16 quadrant-ROM glyphs shared by all text-mode applications.

Concurrent routed traffic (implemented)
-------------------------------------------------------------------------------
The five-client catalog crawl exposed loss when the router discarded every
application frame arriving during another client's next-hop resolution. The
router now holds six ingress frames in its unused page-text arena, retaining
their ingress interface pointers in eight protocol-state cells. This is a
bounded native FIFO, not a host queue. Overflow drops the newest frame;
dispatch preserves order and drains rejected frames before IRQ sleep. The
complete router occupies 4775 linked cells. All 53 routing/probe tests pass,
including queue wrap, overflow, receive ownership, two-router delivery and ICMP.

Combined browser verification passes all 57 UI tests, including atlas graphics,
keyboard navigation, embedded memory inspection, native IRC rooms, network
utilities and snapshots. The production CLI reaches the home page with all 19
CPUs at 10,871,577 world cycles. Type checking and all firmware fit checks pass.
The combined regression run passes all 1603 tests in 118 files, including native
arena boundaries, phase replacement, multi-client HTTP, DNS and snapshot replay.
The maximum-name memory fixture explicitly selects the general DNS profile;
it cannot append a 63-cell record to the expanded world's 24-cell table. The
concurrent ICMP fixture resolves its route before deliberately holding three
HTTP responses, then verifies the measured probe with all three slots occupied.

Final native request audit (complete)
-------------------------------------------------------------------------------
webCatalogCrawl.test runs five independent native clients on LAN a against all
five hosting machines on LAN b. Each client performs its own URL parsing, DNS,
stream connection, HTTP request and response parsing. The observer compares
every returned body cell, including graphical payloads, against the initial
disk content before letting that client select its next URL. No host DNS or
HTTP implementation participates. All 211 pages across 101 hostnames pass at
276,264,027 world cycles, with no guest errors or arena-write violations.
The exhaustive test takes about 14 minutes on the audit machine; its separate
20-minute wall-clock guard and 300-million-cycle bound retain diagnostic
snapshots and a page-count stage if progress stops. Protocol deadlines are
unchanged. GET clients half-close after response EOF, matching the browser,
and use timed NIC-interrupt waits while network work is outstanding.

Acceptance is complete: 100 authored sites plus the atlas, ten closed rings,
cross-ring discovery, 211 reachable pages, eleven native bitmap designs,
keyboard navigation and live memory inspection, bounded native concurrency,
checked startup cost and firmware fit. The combined evidence is 1603 ordinary
regression tests, this exhaustive native crawl, and 57 browser UI tests.
