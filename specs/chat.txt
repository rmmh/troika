TROIKA CHAT/1
===============================================================================

IRC-style subset: nicknames, JOIN, room messages (SAY), POLL and QUIT. This is
not Internet IRC wire compatibility. A dedicated native CPU serves nine clients
and three rooms: 1 lobby, 2 games, 3 workshop. The world web UI includes four
independent JavaScript protocol clients (you, ada, lin, sam), each with its own
physical NIC on LAN b. JavaScript generates client requests and renders replies;
it does not implement server membership, history, admission or deduplication.
The guest browser still runs Forth. This external JS client demo does not add JS
to guest pages, nor establish multi-client support for the existing HTTP servers.

Server: network 1.3.8, NIC 0.0.80, datagram port 194. The supplied clients use
1.3.20..23 and ports 1020..1023. They are explicitly configured same-LAN peers;
this version returns replies to the incoming link peer. Requests and replies
use normal validated protocol-2 network frames with exactly 73 payload cells.
The ordinary frame serial is positive; application request IDs drive retries.

Payload offsets (zero based):
  0       version = 1
  1       request command / response status
  2       request ID, 1..9841
  3       request history cursor / response event ID (0 means no event)
  4       room, 1..3
  5       nickname length, 1..12
  6..17   nickname, ordinary Troika text cells
  18      message length, 0..54
  19..72  message, ordinary Troika text cells

Commands: 1 JOIN, 2 SAY, 3 POLL, 4 QUIT. JOIN supplies an ASCII letter/digit/
underscore nickname, unique among active sessions, and changes the current room.
SAY appends a nonempty message in the joined room, using the stored nickname
(not the caller's claimed sender). POLL returns the earliest retained event in
that room after the cursor. QUIT leaves the room; its reply remains retryable.
A client identity is the complete source network tuple plus source port.

Statuses: 0 success, -1 invalid application input, -2 capacity full,
-3 not joined in that room, -4 out-of-order request ID, -6 event ID exhausted,
-7 nickname in use. Invalid frame structure/length/version/field bounds are
silently dropped without mutation. Error replies contain no history event.

Each session retains its last response. An identical request ID replays that
response without repeating the action; otherwise only the next ID is accepted
(wrapping 9841 to 1). The first JOIN accepts any positive ID. Clients allow only
one outstanding request and retry the exact packet. This is bounded duplicate
suppression, not an unbounded exactly-once promise across reconnects or ID wrap.
Clients retry 12 times with endpoint-specific backoff; a timeout retains the
pending request for the explicit Retry control. Client send queues hold 27 items.

Sessions expire after 9841 network ticks without a processed request. Expiry is
checked on ingress, so idle service requires no timer wakeups. QUIT tombstones
consume a slot until expiry or rejoin. A full table returns an explicit error;
it never overwrites another active client. NIC overflow/loss is handled by
client retries. One response is sent at a time through the physical NIC, while
independent membership, request IDs and responses remain live for all clients.

History is a global 27-entry ring, shared by the rooms; old messages fall out of
history. Event IDs run from 1 through 9841. At exhaustion SAY returns -6 instead
of wrapping into an ambiguous cursor; restart resets this demo's volatile state.
Each JS client retains at most 81 displayed messages. Room changes reset its
history cursor and do not leak other rooms' events into the selected room.
Chat is public and unauthenticated; nicknames are not credentials.

Native RAM (all inclusive):
  2552..2794  nine 27-cell sessions: state, source[3], port, last request,
              nickname length + 12 cells, room, expiry[3], four spare cells
  2800..3699  nine 100-cell cached replies (header plus used payload)
  3800..3899  transient error reply for clients without a slot
  5250..5260  eleven control cells
  7007..9193  twenty-seven 81-cell history records; 70 used + 11 spare each
Normal network, ICMP, filesystem, and native stack regions remain reserved.
All code links in the 9666-cell resident regions; margin holds history, never
code. firmware:report measures the complete image. No hidden server heap.

World UI: choose a client and room using standard keyboard-accessible selects;
type in Message and press Enter to send. Every client can be controlled manually;
ada, lin and sam also send occasional messages at simulated-world intervals.
Pause stops all clients and CPUs. Inspect machines -> chat shows live native
server RAM. Restart and disk restore reset chat; disk checkpoints do not claim
to save volatile conversations or sessions.
