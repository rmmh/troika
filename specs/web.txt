TROIKA MINIMAL WEB APPLICATIONS
===============================================================================
Status: version-1 contract with native URL/HTTP/page/Forth components. Complete
browser and application-server integration is still open. Clients and servers
use the stream in transport.txt and files in storage.txt. Accounts, authentication,
a general shell, permissions and session/cookie semantics are deferred.
Browser origin separation still applies to page code and form submission.

1. URLS AND HTTP SUBSET
-------------------------------------------------------------------------------
Use http://host[:port]/path inside the simulated world only. Host is a DNS
name of at most 54 encoded characters or a bracketed three-tryte address,
e.g. http://[___.___.__N]/index. DNS labels use lowercase letters, digits and
hyphens separated by dots; labels cannot be empty or start/end with hyphen.
Normalize DNS names to lowercase and omit a trailing dot; default port 80.
Ports are decimal 1..9841. Numeric address groups are exactly three tribble
characters each; do not lowercase them. Origin is (world, http, canonical
hostname or numeric address, effective port). DNS aliases remain distinct.

Paths are '/', '/name', or '/app/name', where name is 1..13 lowercase
letters/digits/dot/underscore/hyphen, excluding '.' and '..'. No query string,
percent encoding, fragments, relative-directory traversal or alternate scheme.
A link may contain a full URL or an absolute path on the current origin.
Raw input and canonical URL length are each at most 108 trytes. A form action must be an absolute
'/app/name' path on the current origin; cross-origin forms are deferred.

Native URL API (firmware/include/url.asm):
  url_parse(A=source,B=length) returns A=0/-100 and B=canonical length. It
  accepts case-insensitive HTTP scheme/DNS spelling, removes one trailing DNS
  dot, normalizes decimal ports and omits :80. Numeric groups remain uppercase
  tribble spelling. It emits a full canonical URL at 5954 and a counted path
  within it, using scratch 5711..5818 for the original bounded input.
  url_commit publishes the parsed origin only after application acceptance.
  url_same_origin compares valid current/pending canonical host kind, spelling,
  numeric tuple and effective port. DNS aliases remain different origins.
  Relative absolute paths need an already committed origin. url_form accepts
  only an absolute /app/name path and inherits that origin. World identity is
  the containing machine's World; URLs cannot select another world or the host
  browser/network. Current host/metadata occupy 6062..6122; pending host/path/
  parse state occupy 6123..6195. DNS storage at 6320..6430 remains independent.
  f_validate_navigation uses url_parse for compiled GO. It returns a pending
  action URL only; neither parsing nor GO automatically commits a new origin.
  These component tests do not establish full HTTP/page/browser acceptance.

Request line:  GET <path> HTTP/T1 LF  or  POST <path> HTTP/T1 LF
Response line: HTTP/T1 <three-digit-status> LF
Headers:       Name: value LF
Header end:    LF
Body:          exactly Content-Length trytes, not a NUL-terminated string
All text uses Troika text encoding. LF is the sole wire line separator.
This is deliberately not HTTP/1.1 wire syntax or octet encoding.

Recognized headers:
  Host            required exactly once in requests, including optional port
  Content-Length  required exactly once in requests and responses, 0..9841
  Content-Type    required exactly once when body length is nonzero
Names compare case-insensitively; reject duplicate recognized headers even
if values agree. Header lines are at most 81 trytes excluding LF. The entire
start-line/header section, including LF separators, is at most 486 trytes.
Parse incrementally using shared scratch; never retain all headers.

Decimal numbers contain digits only, no sign; reject overflow. No leading/
trailing whitespace other than the one space after ':'. Reject CR, folded
headers and Transfer-Encoding. Ignore other syntactically valid headers
within the size limits. There is no chunking, compression, keepalive,
pipelining, redirects, cookies or session header processing in this version.
Host must match a configured native-server virtual host (or its own numeric
address/port); no match returns 404, not a different site's default content.

GET has Content-Length 0. POST is restricted to '/app/name', has a body of
at most 216 trytes, and uses application/x-troika-form. Other methods return
405. The server processes one request per stream, returns one response,
then closes its write side. The client waits for the response, consumes it,
then closes its write side; neither needs EOF to delimit an HTTP body.
Extra request/response bytes are a protocol error. EOF before the declared
length is a truncated message. The browser never automatically retries POST
or a request whose outcome is unknown after connection failure.

Statuses: 200 success, 400 malformed request, 404 missing route/host/file,
405 unsupported method, 413 request/body too large, 415 unsupported type,
500 handler/storage failure, 503 temporarily unavailable. Transport busy
before acceptance is RESET(busy), not an HTTP response requiring a second
accepted connection. Error bodies are short text/plain messages.
When invalid framing or a size limit prevents accepting a complete bounded
request, the server may immediately RESET(protocol error) instead of sending
an HTTP error. It must not wait indefinitely to drain rejected input. Normal
HTTP responses are produced after the complete bounded request is received.

Native HTTP component API (http.asm / httpEmit.asm):
  Link http.asm with exactly one role module: httpRequest.asm for servers/full
  request parsing, or httpClient.asm for browser response parsing. The browser
  role returns unsupported-method for request input and omits server virtual-
  host/request policy code. Response behavior is identical. httpEmit.asm is
  charged to server images; httpSend.asm provides browser request headers.
  http_init(A=0 request or 1 response) clears one parser. http_feed(A=source,
  B=0..216) accepts arbitrary stream splits; source must remain stable outside
  scratch/URL arenas 5711..6439. Host normalization uses those arenas and must
  not overwrite unread input. A=0 means accepted so far; h_phase=3 means the
  declared body is complete. http_eof rejects any incomplete header/body.
  http_body(A=raw body cell) is a required native application callback returning
  A=0 or an error. Body cells are binary; text/form validation belongs to the
  consumer. It must not reenter/reset the parser or alter unread source/state.
  Public parser calls reject callback reentry. Application actions must wait
  until the complete bounded request is accepted; callbacks are not a commit
  notification. Extra data in the same or a later feed is rejected.
  Errors are sticky until init: -101 malformed/extra data, -102 size limit,
  -103 unsupported POST type, -104 non-app POST path, -105 busy and -106
  truncated EOF. Callback failures propagate. Unknown methods are recorded as
  method 3 for a server to return 405 after bounded framing. Host mismatch is
  recorded separately for a 404; it never selects a default virtual host.
  A response Host header cannot change current/pending origins.
  Content types are 0 absent, 1 text/plain, 2 text/troika-page, 3 form and -1
  other. Unknown response types are retained for consumer policy. Header names
  use HTTP token characters; other well-formed headers may have empty values.
  http_response_header(A=status,B=length,C=type) emits a complete bounded
  response header into the shared 81-cell line buffer and returns A=status,
  B=encoded count,C=pointer. Type 0 omits Content-Type only for an empty body.
  It does not send data or report an application action as committed.
  http_request_header(A=1 GET/2 POST,B=body length 0..216) requires a valid
  pending canonical URL. GET requires an empty body; POST additionally requires
  a committed matching origin and /app/name. It returns A=0/error, B=header
  count,C=5711. Headers occupy at most 159 cells of existing scratch; send/copy
  them before reusing scratch to encode form data. No extra buffer is allocated.
  The encoder changes HTTP working metadata; call http_init(1) before receiving
  the response. Parser callback reentry is rejected. It neither sends nor
  commits origins/actions, and does not automatically retry any request.
  pageForm.asm encodes binary form bodies; the complete submission loop is open.
  Path storage occupies 6196..6213; metadata 6214..6229 and 6311..6319; the
  single header line occupies 6230..6310. Total 124 existing URL-state cells.

Native integration tests run a client, router and server CPU. The server parses
GET and its Host, reads /www/index via native FAT, derives Content-Length from
checked entry geometry, encodes the response, streams empty and multi-block
files and closes both stream halves. This is a route fixture, not yet the
interactive browser or complete persistent application server ecosystem.

2. FORMS AND NATIVE SERVER DISPATCH
-------------------------------------------------------------------------------
Form body is a compact binary tryte sequence, not percent-encoded text:
  field_count, repeated [name_length, name, value_length, value]
Count 0..3; names 1..13 characters using lowercase letters/digits/underscore;
values 0..54 encoded text trytes. Names must be unique. Reject unknown text
codes, NUL, bad lengths, duplicate names, or trailing data. Maximum body:
1 + 3*(1+13+1+54) = 208 trytes. It fits the 243-tryte shared form scratch.
Fields appear in page order; handlers look up by name, not unchecked position.

Native browser encoder (pageForm.asm, requires pageState.asm/Forth state/url.asm):
  page_form_body() returns A=0/error, B=length, C=5711. It requires a validated
  page containing a form and no active page loader or Forth handler. It writes
  at most 208 scratch cells using current input records; the loader owns field
  names/order/uniqueness, and native input editing preserves their metadata.
  Values are checked for length, text codes and page-arena bounds. A=-113 means
  unavailable/invalid form state; -112 means busy. A failed call may partially
  overwrite scratch but does not submit or invalidate the page. Use output only
  for A=0. No new state cells or hidden body buffer are allocated.
  Freeze input while preparing a submission. Encode once to obtain body length,
  encode/send the request header (which reuses scratch), then encode/send the
  same frozen form body. Resume editing only after that body has been copied or
  consumed by transport. Encoding alone neither sends nor requests an action.
  Server-side form validation and application dispatch remain required.

Filesystem mapping:
  GET /           -> file /www/index on the configured content unit
  GET /name       -> file /www/name on that same unit (name grammar above)
  GET /app/name   -> registered native handler, zero input fields
  POST /app/name  -> registered native handler, validated form fields
No automatic execution of a file and no source-code evaluation based on a
URL. Native firmware has an explicit bounded method/path-to-handler table.
Static routes use the /www directory on the configured content unit (default
0); they never parse a drive selector from a URL. /net.seq and firmware files
outside that directory are not exposed by these routes. The minimal URL
grammar above still selects direct children of /www; deeper filesystem
directories remain available to native handlers. A directory requested as a
file returns 404; there is no automatic directory listing. A missing handler
table entry also returns 404.

A static file is text/troika-page when its first record is the page-version
record below; otherwise text/plain. Files above the HTTP 9841-tryte body limit
return 500 with a bounded message. Static Content-Length comes from the FAT
entry, computed with checked multi-tryte arithmetic before range checking.

A handler validates the complete form before changing application state.
It then performs its action once and chooses status, type and body length.
Rendering may count then emit output from stable state to avoid buffering an
entire response; the counting pass must not repeat the action. Plain static
fragments can stream from disk. Handle filesystem errors before reporting
success for a persistent change. Transport ACK only means bytes accepted,
not that a file write or handler action committed.

Persistent records use the FAT library, not host objects. A multi-file action
is not magically transactional. An action committed before a lost response
may already have happened; use set-state operations where possible, or give
a later status/read operation so the client can determine the result.
Concurrent clients receive transport busy; no hidden server request queue.

3. SMALL PAGE FORMAT
-------------------------------------------------------------------------------
Content-Type is text/troika-page. Body starts with 'PAGE 1' followed by LF.
Then zero or more records. A string is decimal length, colon, then exactly
that many encoded text trytes; the length excludes its prefix. There is no
escape language: delimiters/newlines inside a string are just counted data.
A single space separates record fields; LF follows each complete record.
Record letters are literal uppercase text characters, not numeric codes.

  H string                 heading
  T string                 ordinary text
  B                        line break (no following space)
  L string string          link: label, target URL/path
  F string                 form action '/app/name'; at most one F
  I string string          input: name, initial value; follows F
  S string                 submit button label; follows F, at most one S
  C string                 Forth source definitions

Example body (each displayed newline is one LF):
  PAGE 1
  H 4:Door
  T 6:Locked
  F 9:/app/lock
  I 5:state 6:locked
  S 3:Set

At most 27 records including F/C and at most three I records. Field names and
initial values obey the form bounds. Page body limit 2187 trytes; retained
text/URL/field strings share the 1458-tryte arena. Each input reserves 54 value
cells even if initially empty; these reservations count against that arena.
Flat record descriptors share 486 trytes (27 x 18); forth.txt section 4
fixes their native field layout for the page-word backend. Compiled definitions,
names, literals and fixups share the separate 729-tryte script arena. The
on-wire body limit does not override any smaller allocation limit.

Parse strings incrementally. Do not retain C source after compilation, nor
a second copy of the page body. Plain-text responses have no page records or
scripts and must fit the 1458-tryte text arena. Unknown records, invalid text,
extra fields, bad form order, unresolved words or arena exhaustion invalidate
the page. Clear an old page before loading a new one; no double-buffered DOM.

Native page API (page.asm with resident pageState.asm): page_init(A=1 plain text/2 Troika page) clears the
old text, records, dictionary, variables and flags. page_char(A=one body cell)
or page_feed(A=stable source,B=0..216) incrementally parses content. Feed input
must not overlap page/compiler/scratch/URL state 2552..6439. page_finish rejects
truncation, incomplete compiler state and unbound deferred words, then sets
pp_valid. It does not invoke LOAD or commit a SEND/GO action. The application
must gate all interaction on pp_valid and complete HTTP/stream validation.
The native HTTP/page integration fixture waits for valid EOF before invoking
LOAD, so short or extra response bodies cannot run a compiled handler.

Parser metadata occupies 5420..5438 inside the existing Forth metadata arena.
The source compiler never retains C strings. A literal T or text/plain string
that resembles records or source remains literal. Input values reserve and
zero 54 cells; names remain separate counted slices. Duplicate names, invalid
form order, duplicate F/S, unknown records/text, overflow and truncation make
the whole page invalid. Errors -110 syntax/truncation, -111 size/arena limit
and -112 reentry are reported; URL/compiler errors propagate. Error state is
sticky until page_init, and invalidation clears script/action readiness.

Link validation preserves the pending request URL and origin. Absolute URLs
use url_validate_link, which saves 73 existing metadata cells on the declared
native stack, parses into scratch 5819..5926 instead of replacing the pending
URL text, then restores metadata on success or failure. Relative links validate path syntax and bind to the containing page's
origin on acceptance. Forms validate the required relative /app/name grammar.
HTTP/page/link tests bound observed native stack use by 110 of 243 cells; this
is not yet an interactive-browser worst-case interrupt measurement.

Disk phase interface (pageCompilePhase.asm/pageInteractPhase.asm):
  Both images enter at offset zero through image_call(A=0). B selects the
  operation. Compile phase: B=0 initializes type C, B=1 feeds source C/count D,
  B=2 finishes, B=3 feeds a single body cell C. Interaction phase: B=0 invokes optional LOAD, B=1 encodes the
  form, B=2 draws text C/count D at cursor F/palette G, B=3 encodes request
  method C/body length D, B=4 invokes SUBMIT. B=5 renders the viewport with
  top logical row C and focused record D (-1 for none), returning total rows B.
  B=6 traverses focus from record C (-1 for none) in direction D (+1/-1),
  returning the next focus in B or -1 if no target exists. B=7 edits input
  record C at cursor D: F=0 inserts Troika text cell G, F=1 backspaces,
  F=2 deletes forward; B returns the resulting cursor. Unknown operations
  return -119. B=8 dispatches a page UI event C with optional text cell D.
  B=9 polls one physical text-device key. B=10 prepares the deferred action
  header, B=11 prepares its body after the header is copied, B=12 releases the
  action after body copying or cancellation. B=13 advances request transmission
  on an already-established stream. B=14 resolves/measures the action target
  before connection setup without building its header.
  Missing LOAD is a successful no-op. Missing SUBMIT requests SEND; a defined
  SUBMIT receives no implicit action. Each event starts with cleared deferred
  action state and requires an accepted page. No dispatcher sends a request or
  commits an origin itself. The controller must apply successful actions once.
  forthLookup.asm and pageState.asm stay resident with the VM/page-word backend;
  compiler source code and interaction helpers share one disk-loaded RAM slot.
  Tests preserve page/dictionary data across replacement and reload for another
  navigation. The full browser network controller remains to be built.

Native input helpers (pageInput.asm):
  page_focus(A=current record,B=direction) wraps through L/I/S records, skipping
  all other kinds. page_edit(A=record,B=cursor,C=operation,D=text cell) edits only
  I values, shifts within the existing 54-cell reservation, updates its length
  and clears the vacated tail on deletion. Edge deletion is a successful no-op.
  Both require an accepted page and idle parser/handler. Error -121 rejects
  invalid state/arguments; -122 means a full input. Reentry returns -112.
  No persistent input storage is added. The controller owns focus, cursor,
  keyboard decoding, scroll positioning and the submission freeze: it must not
  call editing between measuring a form body and sending that same body.

Native page interaction controller (pageUi.asm):
  page_ui(A=event,B=Troika insertion cell) stores top row/focus/cursor/readiness/
  follow flag/current character in six cells at 5443..5448. The viewport reports
  its focused record's start row at 5442 (-1 if none). Events are 0 initialize,
  1 next focus, 2 previous focus, 3 cursor left, 4 cursor right, 5 insert,
  6 backspace, 7 delete forward, 8 activate, 9 scroll up, 10 scroll down.
  Initialization selects the first L/I/S; entering an input places the cursor
  at its end. Focus changes bring that record's start into view. Scrolling is
  clamped to the document and does not force focus back into view. Editing
  redraws the current value and caret. Activation on an input or button invokes
  SUBMIT; a link parses
  its target against the accepted origin and queues GO. It neither commits the
  pending origin nor performs network I/O. An outstanding action rejects all
  UI events with -123 until the caller resolves/clears it. Invalid events or
  uninitialized/unaccepted state return -124; parser/handler reentry gives -112.
  Page initialization clears UI state with the existing Forth metadata arena.
  Network submission must keep the pending action until its frozen body is
  consumed or the submission is cancelled, then clear it before resuming UI.

Native edit caret (pageView.asm):
  page_view keeps its original no-caret interface. page_view_edit additionally
  accepts C=cursor (0..54, or -1 to hide it) and renders a caret only for a
  focused input whose length includes that cursor position. Four more metadata
  cells at 5449..5452 hold the requested cursor, caret row/column and target
  address. The native text walk computes the caret position through wrapping
  and literal newlines; no retained layout array is used. Palette 2 marks the
  cell while retaining its underlying glyph. Every input reserves one trailing
  display blank so an exact-width value cannot put its end caret over the next
  record. This does not change input storage or serialized form values.
  The UI follows the caret row when editing an input, otherwise the record's
  start row. Manual scrolling can move it offscreen without moving the cursor.

Physical text-display keyboard (textKeyboard.ts/pageKeys.asm):
  The focused mode-T canvas queues printable ASCII as ordinary Troika text into
  the existing text device. Controls occupy non-text cells: 81 Tab/next focus,
  82 Shift-Tab/previous, 83 left, 84 right, 86 backspace, 87 delete, 88 Enter,
  89 up and 90 down. Cell 85 is reserved. Escape releases canvas focus; host
  shortcuts and composition are not intercepted. This is key translation only;
  the guest decides all page behavior. The serial console remains line-based.
  Native page_poll reads _PA then at most one _PB cell, returns 1 when empty,
  0 on success, or an error. LF also activates, allowing serial-line input.
  Unknown cells are consumed with -125. Invalid page/UI state, active handlers
  or pending navigation/submission leave queued cells untouched. No additional
  guest RAM buffer is allocated. The application must call polling from its
  cooperative event loop; this does not yet supply that full network loop.

Deferred request preparation (pageRequest.asm):
  page_request_target uses the outstanding action: SEND locates F, resolves its
  relative target against the committed origin, measures the frozen form and
  selects POST. GO revalidates its canonical URL and selects a zero-body GET.
  It returns A=0, B=method and C=body length without advancing the request stage.
  page_request_header repeats target resolution and generates the corresponding
  header, including same-origin enforcement for POST. Neither commits an origin
  or performs I/O.
  On success B is header length and C points to shared scratch 5711. The caller
  must send/copy all of it before page_request_body reuses that scratch. Body
  preparation returns B=count/C=5711, including zero count for GET. For POST
  it serializes the frozen values again and checks the measured length.
  Two state cells at 5453..5454 hold stage and body length. Stages 0 -> 1 -> 2
  prevent duplicate/out-of-order preparation (-126); changed body length gives
  -127. Errors leave the action frozen for explicit cancellation or retry.
  page_request_clear releases action and staging after the body has been copied
  or cancellation completes. Native page_edit itself also rejects pending
  actions (-123), so bypassing UI dispatch cannot edit a prepared form.
  Lower-level header/form helpers remain available to trusted native callers;
  the application owns stream backpressure, retries, cancellation and response
  loading. This interface does not yet implement that network controller.

Cooperative request transmission (pageTransmit.asm):
  page_request_send advances the deferred request on an established reliable
  stream. It returns 1 while pending, 0 after FIN is queued, or a negative
  error. The caller must service networking between calls and must not reuse
  shared scratch while this operation is pending. Header and maximum form
  body each fit in one 216-cell DATA packet. The sender retains header length
  and phase in 5455..5456, prepares each part once, retries a would-block send
  without repeating preparation, and waits for the final DATA acknowledgment
  before queueing FIN and clearing the deferred action. It accepts an open or
  half-closing stream through the stream APIs. Errors retain frozen action and
  staging; abort the stream before calling page_request_clear after failure.
  Connection establishment, response handling and automatic retry policy remain
  outside this module. A POST is not replayed on a new connection.

Pending-URL connection setup (resident browserConnect.asm):
  Resolve the action with page_request_target, then call browser_connect_begin
  with A=local port. Call browser_connect_step while cooperatively dispatching
  ingress to DNS/stream handlers and servicing networking. Both return 0 pending,
  1 established or a negative error. Hostnames use the native DNS cache/query;
  numeric hosts bypass DNS. Seven cells at 2493..2499 hold phase, local/remote
  ports, resolved address and status. The resolved address is separate from URL
  origin metadata, so DNS does not change same-origin comparisons. Busy queries,
  active streams or another connection attempt reject begin without replacing
  it. Invalid URL/port gives -128; DNS/stream errors propagate and remain in
  connection status. During setup, link/lease cancellation uses existing DNS
  cancellation and stream abort hooks; stepping then observes their error. No request is replayed.
  Keep the pending URL stable throughout connection setup. Generate the request
  header only after connection succeeds: DNS uses scratch 5711, so preparing
  a header first would destroy it. The application still owns DHCP/ingress
  dispatch, response parsing, accepted-origin commit and navigation lifecycle.

Resident page response loading (browserResponse.asm):
  Install the compiler image before browser_response_begin. That entrypoint
  invalidates old page/script readiness and initializes HTTP response framing.
  browser_response_step consumes at most one held stream DATA payload through
  http_feed and releases it only after successful parsing. A resident http_body
  callback lazily initializes the page from Content-Type and dispatches each
  body cell through compiler operation 3. No whole response buffer is retained.
  Returns are 0 pending, 1 accepted or a sticky negative error. After stream EOF,
  http_eof checks framing, page_finish seals content, and url_commit accepts its
  origin. The caller then loads interaction code and invokes LOAD separately.
  Four protocol cells at 2500..2503 hold phase/start/count/status, surviving page
  metadata resets. Reentry from active HTTP/page/Forth/image calls is rejected.
  Empty untyped bodies become empty plain pages. Statuses other than 200 accept
  only plain error content; executable error pages and unsupported content types
  return -130. Framing, compiler and transport errors invalidate page readiness
  and preserve the previously committed origin. The caller must abort failed
  streams and decide whether to show a local error; this module does not retry.
  Network dispatch and disk-phase replacement must run outside image_call:
  response loading calls the compiler image itself and cannot nest that gate.

Only after the complete HTTP body and page validate does the browser enable
links, inputs and scripts. Malformed/truncated pages show a local error and
execute no handler. There are no images, CSS, frames, background resources,
arbitrary HTML parsing, or network scripts hidden in text/plain.

Native template helpers emit records with computed lengths and literal
strings. Untrusted text normally becomes T content or a form value. A puzzle
server can deliberately use a raw-record insertion helper, turning stored
content into guest page records or Forth definitions. That is the explicit
fictional trust-boundary error; no host HTML/JavaScript executes it.

4. FORTH EVENT AND BROWSER CONVENTIONS
-------------------------------------------------------------------------------
Use conventional Forth syntax with case-insensitive word names. All C records
compile into one page dictionary in source order. The source-level conventions
are settled below; forth.txt specifies primitives, encoding and state bounds. This is a small Troika dialect, not a claim of full
Standard Forth compliance.

  : name ... ;              colon definition
  IF ... ELSE ... THEN      conditional (ELSE is optional)
  BEGIN ... UNTIL           repeat until the popped flag is nonzero
  BEGIN ... WHILE ... REPEAT loop while the popped flag is nonzero
  RECURSE                   call the definition currently being compiled
  EXIT                      return from the current definition
  ( ... )                   non-nesting comment, including stack comments
  \ ...                     comment through the end of the source line

Space and LF separate tokens. Word lookup folds ASCII letters to uppercase;
literal text and field names retain their original case. Signed decimal
tryte literals are accepted; out-of-range literals are compile errors, not
silent wrapping. IF/WHILE/UNTIL consume a flag: zero is false, nonzero true.
Control structures must balance within their definition. A colon definition
becomes visible at its terminating semicolon; use RECURSE for self-calls.

Ordinary calls bind to the most recent completed definition at compilation.
Page words may shadow ordinary built-ins or earlier page words; previously
compiled calls retain their bindings. Compiler syntax words are reserved in
this small dialect. Redefinitions do not reclaim older definitions still
referenced by compiled code; all versions count against the same script arena.

Mutual recursion and forward calls use conventional deferred words:
  DEFER name
  : implementation ... ;
  ' implementation IS name
Declare the deferred word before compiling a call to it, then bind it to a
completed word during page loading. Calls through it use its bound target.
DEFER and the top-level tick/IS binding form are permitted loader declarations,
not general execution of source while a page arrives. All deferred words
must be bound before enabling handlers. Unknown words or unbound references
make the page invalid. Rebinding during event execution is deferred along
with other runtime dictionary mutation. Deferred calls obey the same stack
and execution limits as ordinary and recursive calls.

For example, a page can define its submit hook as either spelling:
  : SUBMIT SEND ;
  : submit send ;
Both select the same case-insensitive names; pages normally use just one.

Optional page words LOAD and SUBMIT are the entry points. LOAD runs once
after successful page validation. Activating S runs SUBMIT if defined;
otherwise the browser submits the form directly. If a defined SUBMIT returns
without requesting submission, stay on the page (for example after local
validation). Hook lookup selects the most recent completed page definition,
case-insensitively. Handler stacks begin empty. There are no per-keystroke
callbacks. LOAD is a browser hook in this dialect, not a block-source loader.

Proposed browser words, with stack effects:
  FIELD@ ( index -- address length )  input index 0..field_count-1
  TEXT!  ( address length record -- ) replace an H/T record's literal text
  SEND   ( -- )                      request submission of the current form
  GO     ( address length -- )        request navigation to a valid URL/path
FIELD@ returns a bounded guest slice. TEXT! may change length only within
that record's original string capacity; no new records, heap growth or code
compilation occurs. SEND/GO schedule one action after successful return.
A second action request in one handler is an error; it does not queue another
connection. Copies needed for pending actions count against existing state.

Underflow, overflow, bad reference, invalid URL or execution-budget exhaustion
ends the handler, clears stacks and discards its pending action. Earlier text
changes need not roll back. No raw socket, host reference, unrestricted native
memory write, asynchronous request, event queue or runtime dictionary mutation
is exposed. Navigation clears the old dictionary and page-owned slices.
Account/login policy can later build on these conventions without enlarging

5. ACCEPTANCE
-------------------------------------------------------------------------------
Serve static files and one dynamic form entirely through native firmware,
across a router. Exercise HTTP framing split at every packet boundary, short
bodies, extra data, duplicate headers, line/body/arena limits, malformed form
lengths, full disks and failed commits. Verify one action per request, no
implicit POST replay, no script before complete validation, and no execution
of text/plain or counted literal text. Demonstrate GET, POST, LOAD, SUBMIT,
built-in/defined/recursive words and origin checks within measured guest RAM.
Check mixed-case lookup, comments, early EXIT, balanced control structures,
RECURSE, DEFER/IS mutual recursion, shadowing with stable compiled bindings,
unbound deferred words and dictionary exhaustion after redefinitions.

Source-language references: https://forth-standard.org/standard/core/Colon,
https://forth-standard.org/standard/core/RECURSE and
https://forth-standard.org/standard/core/DEFER. Troika's bounded loader and
browser environment are explicitly smaller than a general Forth system.
