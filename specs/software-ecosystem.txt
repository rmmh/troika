TROIKA SOFTWARE ECOSYSTEM
===============================================================================
Objective: at least 1000 different working programs and related software,
distributed across the world's fictional websites where they belong.

Acceptance requires executable behavior, not 1000 filenames, renamed copies,
constant substitutions, or descriptions of programs that do not exist. Shared
libraries and UI code are expected; each counted application must have a
distinct purpose, implementation or materially different interaction. Catalog
entries must describe inputs, outputs, controls, limitations and ownership.
Pure article pages, artwork and test fixtures do not count as applications.

Standalone applications are native PRG images executed by the existing checked
disk loader. The protected program core remains resident; downloaded code runs
on the same 19683-tryte CPU. Interactive page software uses the native bounded
Forth compiler and VM. Runtime algorithms, graphics, sound, input and storage
must execute in guests, never in a host-side application interpreter. Host-side
assembly and initial media construction are permitted build steps.

Distribution must preserve existing articles and webrings. Site software shelves
link to descriptions, runnable pages and downloadable binaries/source as
appropriate. Examples should span development tools, text/data utilities,
mathematics, simulation, graphics, sound, games, creative writing, personal and
community applications. A manifest must enumerate real software and associate
each item with its site, source, artifact, behavior and native verification.
Counting is an audit of that manifest, not a target manufactured by a generator.

Infrastructure work must account for larger disks, bounded directory/path and
page sizes, native startup checking, host selection, MIME types, downloads,
keyboard launch/exit and memory/phase budgets. Existing software and saved-media
error recovery must continue to work. Distribution throughput and cold boot must
be measured with the real population; empty or undersized test media cannot
prove the final ecosystem is usable.

Progress
-------------------------------------------------------------------------------
The native program selector now accepts a counted disk path (option 4, at most
18 cells). Letters are folded to lowercase; backspace edits, Enter loads, and
F1 cancels. The existing three built-in programs remain selectable. A native
keyboard test covers missing files, checksum failures, editing, launching a
separately linked PRG and returning to the menu with the protected core intact.
The loader's corruption tests and existing Terminal/IRC switching also pass.
Four native utilities now ship on ternary.world: common divisor, integer square
root/remainder, radix digit census, and prime factor census. Each has distinct
native algorithm code, documented inputs/outputs, example/error vectors and a
PRG download. The reusable softwareUi module supplies keyboard numeric editing,
signed input, Tab selection, decimal output and F1 exit; it contains no Forth,
HTTP or host application callbacks. Each image is linked against the running
production core. Algorithm source is available alongside the binary.

All four applications execute their example vectors using native keyboard I/O
under code/arena write guards. softwareWorld browses the real shelf, fetches a
binary through routed DNS/HTTP, checks the saved file, loads it with option 4,
computes gcd(84,30)=6 and returns to Web. The catalog stores binaries and sources
as real native files. The virtual-host server uses a native path allowlist to
mark these files text/plain (the transport's existing raw download convention);
ordinary pages retain their Troika-page type. Firmware reports include the
actual software files, protected-core cost and populated server disks.
The real-browser keyboard/download/inspection test also passes; its screenshot
shows the native UI and value 6 at guest address 2560. Programs publish their
manifest identity in cell 2533 (2532=4), allowing the debugger to select their
linked symbols without interpreting or executing their algorithms. The first
four files occupy 506..567 cells each, and core+application totals are
2987..3048 of 9666 ordinary code cells. The hosting disk retains 55/243 free
blocks; the complete browser still has 207 of 12501 code cells free.

The next batch adds fraction reduction and signed division on ada.world,
cycle alignment on clockwork.world, a bounded hailstone-orbit explorer on
orbit.world, Josephus circle elimination on scorebook.world, a three-heap Nim
coach on mancala.world, Hamming encoding and CRC-8 on signals.world, exact
recipe scaling on hearth.world, and unordered-selection counting on
cardtable.world. These are distinct native algorithms, not renamed variants.
Arithmetic helpers remain guest assembly. Domain and overflow failures are
explicit rather than returning wrapped answers as useful results.

Verification now covers 444 physical-keyboard vectors, including all 16
Hamming inputs, all 91 permitted binomial selections, 64 small Nim positions,
125 CRC byte triples, signed division boundaries and recipe products exceeding
a tryte. Every one of the 14 native binaries is downloaded through routed
DNS/HTTP and compared byte-for-byte with its artifact. That same test launches
four programs from different sites, checks live computed results, and returns
to Web between launches. All 234 populated pages pass the native parser; the
link graph includes software shelves, descriptions, binaries and source files.
Type checking and firmware/media fit checks pass. Programs occupy 506..636
file cells and at most 3117/9666 cells including the protected core. The most
populated server disk still has 27 of 243 blocks free at this stage.

This is 14 applications across nine sites toward 1000. Additional categories, sites and programs,
large-population media/startup measurements and comprehensive final distribution
verification remain outstanding. The goal is not complete.
